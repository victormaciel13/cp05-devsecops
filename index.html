Depois do vazamento de uma chave de API num commit público, a Arcanjo SA exige um pipeline de segurança em todo repositório. Este site é o repositório de referência.

Os portões de cada push

  1. Gitleaks Varre o histórico do Git atrás de senhas, tokens e chaves de API. Encontrou um segredo: pipeline barrado.
  2. Semgrep Análise estática do código-fonte (SAST). Procura padrões perigosos, como eval() executando texto vindo do usuário. Encontrou: pipeline barrado.
  3. Código limpo Os dois portões passaram: o commit segue para build e deploy.

Por que isso importa

Um segredo que chega ao GitHub precisa ser considerado comprometido, mesmo que o commit seja apagado depois: ele continua no histórico e em clones. Barrar antes é muito mais barato do que revogar e investigar depois.

Já o eval() transforma qualquer texto em código executável. Se esse texto vem da URL ou de um formulário, um atacante consegue rodar o JavaScript que quiser no navegador da vítima (XSS).
